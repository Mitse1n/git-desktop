## 结论与证据范围

主要收益集中在完整历史刷新、工作区变化时的界面更新，以及没有共同文本行的大幅重写 Diff。普通小仓库打开并非所有操作都会更快，缓存也有内存成本。本文同时公开未改善的数据，不把控制器耗时称为屏幕响应或帧率。

此次没有新增可靠的 IDEA 可见响应计时，因此不能从这些数据推出“比 IDEA 快多少”。[原始调查报告](performance-report-2026-10-12.md)保留 IDEA 现场内存采样及其条件差异；[可复用测试方法](performance-testing.md)给出同仓库、同操作的 IDEA 对照流程。

## 六步代码优化与保护措施

| 步骤 | 最终修改 | 如何避免影响表现和正确性 |
| --- | --- | --- |
| 1 | 双栏 / Unified 切换复用当前 Diff 及 Unified 行缓存 | 保留原有列配置、异步应用顺序和导航重置；不缓存多个文件 |
| 2 | 新请求取消已过期的文件读取和计算，队列逐项释放临时对象 | 文件 / 请求令牌同时校验；取消不返回部分结果；保留原有加载语义 |
| 3 | 只有工作区状态变化时，不重建未变化的日志、分支和提交详情 | 比较完整历史相关状态；仍更新状态、操作按钮、工作区及选中文件；模块配置变化仍重建分组 |
| 4 | 单项完整祖先拓扑缓存，刷新不反复扫描全部历史 | 每次重新读取所有 refs/HEAD 和 shallow/grafts；支持 linked worktree 的 common dir；不缓存工作区状态 |
| 5 | 将值类型的图布局和当前分支可达集合准备移出主线程 | 保留图算法、分支头顺序和颜色规则；切换时校验快照 / epoch，避免旧结果覆盖新状态 |
| 6 | 对共享行唯一且顺序一致的 Diff 使用精确快速路径 | 重复共享行或重排继续使用原标准库算法及其对齐规则；保留二进制、大小、行数和末尾换行语义 |

祖先缓存不仅检查命中条件，也检查发布条件：首次扫描前后重新验证引用、边界内容和引用目录 / 文件的代际信息。扫描过程中发生引用变动、包括变动后恢复的 ABA 情形，不发布该缓存。无法可靠读取代际信息时放弃缓存；暖刷新命中不递归扫描引用目录。引用数超过 256 时采用原有完整遍历，不启用祖先缓存，避免验证扫描使首次打开回退；工作区增量更新和后台准备仍有效。Git 多条查询本身仍非原子事务，外部并发改仓库时不会承诺一个跨命令事务快照。

每步都执行回归和阶段性能测量。01–06 阶段产物保存在同一输出目录；早期探针只设置窗口初始尺寸，实际被 AppKit 收缩，因此只保留作阶段诊断，不与本文全尺寸数据混算。13-build-overlap-diagnostic 是发现与回归编译重叠后终止的构建，不参与结论。13-final 显示无限制引用校验导致首次打开回退，14-stat-check 用于定位成本；最终采用轻量文件信息读取和有界缓存资格，不使用这两组作为交付版数据。

## 剩余边界和后续方向

1. 重复共享行或大范围重排仍走标准库 Diff，最坏复杂度和瞬时内存尚未整体解决；进入该调用后不能在内部中断。后续替换算法必须先证明旧对齐规则等价，不能采用更快但改变结果的近似锚点。
2. 新仓库首次加载仍需读取全部祖先、状态和 refs；缓存不会消除首次扫描成本。大量分支的主线程仍有布局 / 原生控件工作，当前测试不是 FPS 证据。
3. 搜索维持原有 2,000 / Load More 10,000 的范围，不是 IDEA 的全历史索引；不能比较结果范围不同的搜索快慢。
4. 本次内存是探针本进程，不包括短暂 Git 子进程；完整应用、多窗口、滚动、长会话及 IDEA 同仓库可见操作需用测试文档中的采样和录像流程补充。
5. 保留现有自动刷新周期、主题、文件预览限制和所有业务写操作语义。下一轮应先针对实测剩余热点采样，继续以结果等价和交互回归为前提。
